# article-to-social · 文章转小红书 / 抖音图文

## 这个 skill 解决什么

输入一篇 AI / 科技类文章（也兼容其他领域），输出一套可直接上传的图文：
封面 + 内页的 3:4 卡片 PNG、标题候选、正文、话题，以及一个汇总单文件 HTML。
**两个平台一次做完**（同一份内容 + 同一套 UI，只有 4 处版式差异）。

**不包含自动发布。** 发布走各平台官方入口，由用户点最后一下。
原因是全自动发布会让账号承担封禁风险，详见 `references/why-no-autopublish.md`。
> 抖音侧另有一份**已验证可跑通的半自动填充方案**（停在发布页，不点发布），
> 见 `references/publish-automation-quark.md`。

### 发布时的两条硬约定

1. **点「发布」永远由人点。** 脚本最多做到「填好内容停在发布页」，填完立即退出。
2. **抖音的「自主声明」固定选「内容由AI生成」**（2026-10-05 用户更新）。
   ⚠️ 历史口径「必须勾选 AIGC 标签」「不代操作代填」**均已作废**。
   小红书侧当前无此项强制要求。

## 主干流程（⓪ → ⑧，两平台共用）

### ⓪ 选题发现（用户说「今天发什么」「帮我找点素材」时执行）

#### 🚧 与「常规热榜」严格分离（用户 2026-09-29 明确要求）

**本环节产出的是「AI 科技选题池」，不是「今日热榜」。两者必须分开，不得混在一份文件里。**

| 属于本池（用） | 不属于本池（不用） |
|---|---|
| 今日热榜的**科技 / AI 分类节点**（媒体源，带原始链接与热度） | **抖音热搜 / 微博热搜 / 百度热搜 / B站热搜 / 快手热搜** |
| **X 聚合站**（境外 AI 前沿，二手转载需回一手核） | 影视票房、音乐榜、App Store 榜、报纸版面 |
| **GitHub Trending**（工具向补充） | 任何「社会话题榜」「吃瓜榜」 |
| Hacker News / Reddit（需 VPN，技术社区） | ~~抖音总榜~~ → **仅抖音选题时用**，见 `references/sources.md` |

理由：常规热榜是「今天大家在聊什么」，跟账号的 AI / 科技定位错配，
混进来只会把选题池稀释掉。**要看常规热榜就单独出一份，别合并。**

#### 🚧 选题不看用户背景（用户 2026-10-01 明确要求）

**做选题发现时，不要把用户的个人背景、职业经历、以往内容方向当作筛选或加权因素。**

- ❌ 不做「这个跟他以前的经历有关，优先给他」
- ❌ 不做「这不在他的舒适区 / 他没做过这个方向，略过」
- ✅ 只按内容本身判：**此刻热度 + 可做度 + 与账号 AI/科技定位是否匹配**

> **AI 与科技是并列的两条内容线，不分主次**（用户 2026-10-08 明确）。判选时**不要用「非 AI 主线」否掉科技类选题**
> ——消费电子、智能汽车、生命科学、基础科学、航天能源都是账号内容，与 AI 模型同级。
> 唯一该排除的是**与科技无关的社会话题**（见上方「与常规热榜严格分离」）。
> 反向约束也成立：**一条纯科技新闻也不要因为「跟 AI 没关系」而主动降权或剔除**。

#### 排序规则（2026-10-08 用户明确，四个维度）

候选条目**合并成一份池**（AI 条目与科技条目混排，不分区），按以下顺序排：

| 维度 | 口径 | 说明 |
|---|---|---|
| **⓪ AI : 科技 配比** | **两类各占约 1/2** | 不是死数，看当天实际数量，但**AI 类每天至少留 2 条**。**推荐区（今日最值得做的 N 条）里 AI 类占 1/3～1/2**，不能全是消费电子 |
| **① 平台数量**（主排序） | 该事件被**几个不同来源**命中 | 「N 源命中」直接写在卡片上。单一来源的条目**统一沉底并标「单源待核」**，不与多源条目并列高位 |
| **② 热度**（次排序，同源数内比较） | 节点自带的热度字段 | ⚠️ **口径不可横向比较**，见下方「热度口径」一节。有热度值的才填，没有的留空，**不要用推测值** |
| **③ 条数上限** |单源条目总共只写前 20 条；多源不限 |单源冗余最高、最不适合直接做图文 |
| **④ 赛道配额** | 同一赛道最多 `20//4 = 5` 条（补位时放宽到 7） | 🚦 **2026-10-09 实测踩坑**：只按热度排序时，威锋 15 条苹果 + 10 条 AI 把有热度的名额吃满，**基础科学 / 消费电子 / 智能汽车全被挤掉**。诺奖有 2 个角度也进不来 |
| **⑤ 可做度** | 有「可做角度」的条目优先于纯信息条目，热度降为同层微调 | 🚦 同源踩坑：`iOS 27.0.1 修复若干错误`（热度 5377）排在前面，真正的钩子（尊界V800 多方回应、诺奖、AI 数学证明）全被截掉 |

**实现顺序不可颠倒（2026-10-09 反复返工后定稿）**：
**赛道轮转取 → 类别预算（AI/科技各一半）→ 空位补回**，任何一步都**不允许替换已入选条目**。
反过来（先按热度取满再裁赛道）必然被高热度单一赛道吃掉。

**track='AI' 是个大筐**，要按关键词再分一层（AI模型 / AI应用 / AI行业），
否则 10 条 AI 算「同一个赛道」，配额形同虚设。

- 两维度**冲突时以平台数量为准**：5 源命中但都没有热度字段 > 2 源命中但有一个 8000 阅读量。
- **单一来源的科技类条目允许入池**（科技垂直源本来就少），但必须标「单源待核」并写清缺哪一手源。
- 排序结果不做「AI / 科技」分区展示，只在每条卡片上打**赛道标签**（如「消费电子」「智能汽车」「生命科学」）+ **大类标签**（AI / 科技）。

> **单源上限的用意**（用户 2026-10-08 原话：「你这内容太长了，我要划比较久」）：
> 单源条目冗余度最高、也最不适合直接做成图文，所以**先砍单源**。
> 命中 2 源以上的条目信息已被交叉验证，是优先阅读区，**不要限制条数**。

#### 🚧 选题阶段**不做**成品去重（2026-10-08 用户明确，覆盖旧规则）

**旧规则已废止**：以前会在选题池里把「跟已有成品重复」的条目直接剔除，导致内容单薄、
且同一产品的不同方向被误杀。**现在改为：正常排序、照常写出来，只在条目标题前加一个备注。**

| 情况 | 做法 |
|---|---|
| 与某条成品**同一事件** | 标题前标 `可能做过` |
| 同一产品/公司但**角度、结论、时间线不同** | 标题前标 `可能做过（换角度）` |
| 无关 | 不标 |

- 判定依据 = 扫成品目录 `<小红书根>\`、`<抖音根>\` 下所有 `<日期>_<主题>` 目录名 + 它们的
  `card.json` 标题，一轮扫完、不逐个打开。**扫不到就当作没做过，不要猜。**
- ⚠️ **备注只是提示，不是过滤**。后续做不做由用户在选题阶段挑，不由 AI 提前替用户砍掉。
- **成稿前的去重（同一选题不重复出图文）仍然有效**，与本条不冲突。

抓取时要求：保留小标题、全部数字、公司名 / 产品名 / 人名、引用原话。**不要让它总结。**

### ② 提纯：抽出事实内核

从正文里抽出结构化的事实清单：数字、版本号、机构名、时间点、结论、争议点。
逐条与原文对齐，**不得漂移、不得外推、不得补全原文没说的因果关系**。

### ③ 事实核验（必做，不可跳过）

**这一步是本 skill 与普通「一键生成」工具的核心差别。**

用 WebSearch 对事实内核里的关键点做交叉检索，按三级标注：

| 级别 | 判定标准 | 处理方式 |
|---|---|---|
| **L1 共识** | ≥3 个独立来源一致，或官方（官网 / 财报 / 官方博客 / 官方公告）直接发布 | 正文正常写，**不必逐条标来源** |
| **L2 据报道** | 1–2 个可信媒体来源（主流科技媒体、正规财经媒体） | 正文用「据报道」「XX 称」，**一句带过** |
| **L3 爆料 / 传闻** | 社交媒体、社区流传、单一匿名源、泄露截图、厂商自述 | **必须在图文里显式标注「未经官方确认」**，且不能写进标题当结论 |

同时必须做的三件事：

- **找反方。** 至少检索一次「质疑 / 反驳 / 不能证伪 / 未经验证」这一侧。原文说得越绝对，越要找平衡信息。
- **修正原文的绝对化表述。** 原文常见的「碾压」「彻底告别」「壮士断腕」这类词，
  在核验后如果缺乏支撑，改写时要降级为「在这组测试中超过」。
- **写清分歧。** 多个来源互相矛盾时，把两种说法**并列写出**，不要挑一个当定论，也不要取平均。

核验结果要落成一张表（信息点 / 来源数 / 级别 / 备注），放进 ⑦ 的汇总 HTML。

**⚠️ 选题池里的判断，出成品前必须逐条回搜验证（2026-09-30 踩坑）**

从 ⓪ 选题发现产出的池子里挑条目时，池子里写的「数字」和「落差/冲突」是**当时的快速判断**，
不是已核验结论。进 ③ 时必须把它们当**待验证的假设**。

实测踩到的两类坑：

1. **数字被记错**：池子写「缓存输入价从 $1 降到 $0.10」，核验后实为 **$0.20 → $0.10**
   （$1 是另一个型号的缓存价）。这类错误来自把同批新闻里两个型号的数字串了行。
2. **「落差」是编出来的**：池子写「国内标题写成『因新模型太强叫停发布』」，
   回搜后**找不到任何一篇国内标题作此表述**。整条内容原本就靠这个落差立住，
   不验证直接写，等于替读者编了一个因果。

处理原则：池子里的每个**具体数字**都要回到一手源核一遍；每个**口径分歧 / 反差**
必须能指名到具体来源的具体表述。**验证不通过就换角度** —— 这是「事实与推测分栏」的底线。
换角度后的写法示例：把「国内标题说太强」换成可验证的反差
——「跑分 98%/99.9%/100%，却因可靠性不达标被按下」。同样有张力，但每句都能核。

**完整规范见 `references/fact-check.md`**（含三级标注细则、分歧处理、
来源署名规则、抖音 AIGC 标注与发布端约定）。

### ④ 结构重组（**先重组，再改口吻**）

**不要顺着原文的段落顺序改写**—— 那是洗稿的特征。按三步走：

1. **拆**：把 ② 的事实内核拆成彼此独立的信息点，脱离原文叙事顺序
2. **重排**：选一个阅读骨架，**骨架不得沿用原文的**：
   - 结论先行（评测、数据类）→ 对比反转（争议、辟谣类）→ 时间线（事件演进）
   - 问答（高密度干货）→ 数字拆解（单点数据冲击）
3. **重述**：换句式而不只是换词；连接词改口语方向；段落长短打散

**重制的底气来自「信息增量」** —— ③ 核验查出来的版本时点、反方声音、口径分歧、
原文里对自己不利的平衡信息，都是原文没有的内容。若找不到 2 条原文没有的信息，
说明 ③ 没做透，回去补查。

> 📄 **抖音额外必做**：定「第 1、2 张」—— 第 1 张抛钩子且**不要把结论说完**，
> 第 2 张必须是第 1 张没有的新信息且能独立成立。
> 每张卡片都要能单独看懂，不依赖上一张的上下文。
> 完整规则与排序示例见 `references/rewrite-structure.md` 的「零、抖音特有前提」。

### ⑤ 改写：平台口吻

**通用要求：**

- 开头用钩子（悬念 / 冲突 / 数字冲击），不要用「今天我们来聊聊」
- 英文技术术语（Three.js、Token、Prompt、Agent）保留原文，不硬翻
- **标题 / 笔记标题一律用中文**（型号名、产品名可保留英文，如「Gemini 4 Pro」）
- 🔴 **不写互动引导**（2026-10-08 用户明确）：图上与正文都**不写**「你会在评论区发表一下观点」
  「你怎么看」「分享给朋友」这类话术 —— 属引导评论 / 引导第三方分享，正常陈述内容即可。
  正文收尾就收在**内容本身的最后一句**，不硬凑提问。
- **读者索要链接 / 资源时**（**仅用于回复读者**，不写进图上或正文）：话术统一写「要的，评论区留言」
  —— 不加说明性长句，也不写「私信发你」
- **去 AI 味（轻量、成本低、必做）**：删掉「值得注意的是」「综上所述」「不仅…而且…」
  「在……的背景下」「这标志着」这类书面连接词；**不要三段排比**、
  **不要「首先 / 其次 / 最后」**、**不用「赋能 / 打造 / 闭环」这类空词**。

- **正文必须用 emoji 做小标题分段**。实测有效结构：**开场 1–2 段纯文字**交代事实

**② 密度口径（2026-10-08 改）**

- 阈值 `fillLo=58` / `fillHi=92`（原 78/90）。**`LOW` 不再是问题**：不阻断、不触发任何修改。

  此前追 78–90% 反而偏满。用户口径「填充 60% 以上就行」与行业惯例一致。
- `autogap` 会把块间距在 20–70px 自动收敛到目标区间，**不要手工调 `gap`**。

**③ 字号已固化，不要每次重估**（抖音整体上浮一档，靠 `[data-platform]` 覆盖 `--fs-*`）

行高 1.26–1.7（正文 ≥1.5，行业常规）；内边距 92/88px，间距取 8 的倍数。

**④ 🔴 看图规则（省时间的关键）**

#### 排版硬要求

- 每页一个主题，**单页容量参考**：4 条 item（标题 + 2 行说明）或 5 条 point（每条 ≤2 行）
- 数字用等宽字体 + 强调色突出
- 涉及未证实数据时，页首加琥珀色警示框

**排版密度（2026-10-08 更新口径，取代旧 75–90%）：**

- 内页 `.in-items` 的 **gap 用 46px** 起步，`autogap` 会在 20–70px 间自动收敛，**不用手调**。
- **填充度目标 60–88%**（行业惯例留白 30–40%）。
  **低于 60% 只是偏空，不阻断、不要求补内容** —— 别为填满去加话。
- 唯一要处理的是 `CROWD` / `OVERFLOW` / `WRAP`：内容超一页时**删一条**，不要缩字号。
- 每页字数区间见上面「排版参数卡」。

#### 封面（最容易翻车的一页）

- **封面不要放来源，也不要放日期。** 左上角只放分类 chip（如「AI 前沿」），
  右上角放**栏目词**（模型发布 / 行业事件 / 新物种 / 工具推荐 这类 2–4 字的归类）。
  封面是抓点击的位置，塞来源名会削弱视觉焦点。
  > ⚠️ 右上角**曾经写的是日期**，2026-09-29 用户否决：「封面不写日期，我可能会提前做。」
  > 日期只放正文与页脚。**不要再改回日期。**
- **封面大字优先给「读者已经认识的东西」**（2026-10-06 修订）。
  - ❌ **旧规则「模型名 / 产品名」是错的**：产品名恰恰是读者**最不认识**的东西。
    2026-10-06 用户明确否决：「很明显大家比较知道的是英伟达，这个正常应该是用大字写出来的。」
    把 `Beam` / `textGrain` / `Kolibri` 放最大字号位，读者划到封面依然不知道是什么。
  -✅ 大字按认知度排序取用：
    1. **已知大公司 / 机构**：英伟达、OpenAI、Google、Meta、字节、腾讯…
    2. **读者普遍熟悉的产品 / 概念**：微信、芯片、ChatGPT 类
    3. 都没有时**用品类词兜底**：「又来一个新模型」「开源大模型」——不要用没人知道的产品名
  - 三个已验证范例（2026-10-06）：

    | 选题 | 大字第一行 | 第二行 |
    |---|---|---|
    | Beam | `英伟达投资了` | `一家开源模型公司` |
    | textGrain | `OpenAI` | `给文字打隐形水印` |
    | Kolibri（无人熟知） | `又来一个新模型` | `单张H200就能跑` |

- **封面的第二行要制造认知落差，不是制造惊讶**（2026-10-06 修订）。
  2026-10-06 用户原话：「封面要有钩子」——钩子要真实：
  - **好的落差**（读者读完会觉得「原来如此」）：官方自己承认别人更强 /
    网传说法官方表格里根本没有 / 数字反而比对手大 / 单卡就能跑
  - **坏的落差**（读者读完觉得被标题党）：省略主语（「某公司发布新模型」到底是谁？）、
    夸大最高级、只留悬念不给信息
  - 没知名度的选题，钩子落在**利好**上而不是「是谁发布的」——
    「又来一个新模型」+「单张 H200 就能跑」比「德国实验室发布 Kolibri」更有效。
  - 避开「地域+实验室」这类无认知度词做大字（「德国实验室」没人知道），
    但可留在 kicker（小字）里做补充信息。
  - ⚠️ **不要用「震撼 / 惊了 / 绝了」**：平台限流，且 CHI2021 实测这类标题特征
    并未带来更多点击（详见下方「钩子的心理学依据」）。
- 🔴 **封面钩子 = 选「读者能立刻自问的利益点」，不是选「技术变化最大的点」**
  （2026-10-07 用户否决一次真实返工）。
  **误判实例**：EmbeddingGemma 2 的封面押「终于不绑协议了」，把 `191MB` 只当角落装饰。
  但协议变更是**开发者**关心的，普通读者读完没有实感；
  而「191MB 手机本地跑」是**所有人都能立刻判断自己要不要关心**的利益点。
  **自查方法：看末页收在哪条主线上** —— 末页的结论预设了哪条主线，封面就该押哪条。
  案例：正文主线本来就是「本地」，末页也落在「你会为了隐私放弃云端吗」，
  封面却押「许可」= 自己和自己打架。
  →同一个题材通常有多条候选钩子（本地跑 / 协议干净 / 性能涨分 / 成本降幅），
  **选受众面最宽的那条当封面，其余降级到内页**。
  → **连带要改页序，不只改封面**：封面钩子也是承诺，必须在**前两页**被兑现。
  该案例把「内存账」页从第 5 位提到第 3 位、许可页降为第 5 位，
  否则就是「封面承诺悬空」，与「标题—内容一致性」同一条规则。
- **单行容量上限（2026-09-30 实测）**：`cv-title` / `cv-title2` 为 `font-size:118px`，
  卡片内容宽 904px → **一行最多约 7 个汉字**。写 8 个字会换行，把封面挤乱。
  - 中文 7 字以内安全；
  - 想放更长的话，中英混排（`GPT-6.1 Sol` 这类拉丁字符较窄，11 个字符仍在一行内）；
  - 第一行写成「拉丁模型名 + 4 个汉字」时收到 `100px` 更稳：
    `style="font-size:100px;letter-spacing:-1px"`；第二行保持 118px，视觉宽度反而更齐。
  - 出图后**必须回看封面 PNG 确认没有换行**。

#### 来源标注的位置

> 🔴 **上位原则（用户 2026-10-07 立，整个项目通用）：对外展示 ≠ 内部严谨。**
>
> **内容是给普通观众看的，不是给核查者看的。** 抓取和数据核实必须在内部做扎实，
> 但**不要把核查过程搬到图上或文案里**。判断标准只有一条：
> **「这句话是帮读者看懂，还是在向读者证明我们做事严谨？」** 后者删掉。
>
> 具体到对外产物：
>
> | 内容 | 内部（我核查） | 对外（观众看到） |
> |---|---|---|
> | 自建榜 vs 官方榜 | 用什么源、交叉了几次、API 核过| **一句话**：「按 7 天新增 stars 排名」 |
> | 抓取时点 | 精确到时分、时区 | **只写日期** |
> | 核查缺口 | 哪里没查到、几手来源 | 不出现 |
> | 结论可信度 | 交叉核验记录 | 不出现 |
>
> **反面教材（2026-10-07 周榜末页）**：写了「不是 GitHub 官方 trending 页原样，
> 官方页算法偏向有提交历史的英文代码项目」「增量取自两个自建榜交叉，星数已用
> REST API 逐个核对」「榜单效应值得看但别急着当结论」——**全是我自己的核查笔记，
> 占了整整一节，观众零收益，还把「这榜靠不靠谱」的疑虑塞给了他们。**
>
> 同理，**我们自己的思考/运算过程、以及可能触及法律或平台违规风险的内容，
> 不是照搬到图上，而是优化成合规表述**（例：内部讨论过的对比/推断，
> 对外只留可公开、可验证的部分）。

- **来源统一放最后一页底部，且只写一行媒体名**：`来源：36氪 · 新智元`
  **不要附加原标题、日期、免责说明**（用户原话：「来源：36氪 · 新智元 就可以了，
  不需要写那么多」）。小红书对应 `.in-foot`，抖音对应 `.in-foot .src`。
- ⚠️ **但「一行媒体名」是给新闻转载类内容的做法。** 自建榜单 / 自测数据这类，
  一行媒体名放不进去（没有媒体名），改为**一句口径说明**即可，
  不要因为「必须有来源」就硬凑一段核查说明。
- 榜单类内容**不单独设「口径来源页」**（2026-10-07 用户明确删除该页）：
  一句话塞进封面 `desc` 或末页 `sub` 即可。
- 未证实内容（L3）的「未经官方确认」警示**不放末页脚注**，而是照常放在对应的内容页
  （如参数页页首的琥珀色警示框）—— 既不啰嗦也不丢合规。
- **末页加脚注会挤压内容高度**：改完必须**肉眼复核末页**。

> 是否保留来源，判断依据是「二次创作 vs 直接搬运」—— 重制图文 + 自绘卡片本来就安全，
> 标来源是低成本加分项，不是免责牌。详见 `references/fact-check.md`。

> 中文字体的实际位置与缺失项。下方用变量代指：
> `$NODE` = Node 可执行文件，`$NODE_PATH` = 含 playwright-core 的 node_modules，

```bash

```

也可用 `PW_CHROMIUM` 或 `PLAYWRIGHT_BROWSERS_PATH` 显式指定。

所以**每个卡片 div 必须写 data-export**，文件名即导出名。

### 标题—内容一致性（第一原则，2026-10-06 用户确立，优先级高于下面所有条目）

> 用户原话：「提不提到并不是一条硬规则，而是一个逻辑问题。常规来说，你讲的主要内容
> 肯定是要提到的。写的时候还是应该多注重这种逻辑性，比如你的正文第一页标题叫『是什么』，
> 但实际内容却没有关于『是什么』的介绍，那肯定是不合理的。」

**核心：每页标题都是一个承诺，内容必须兑现这个承诺。**

先定标题，再问「这页要回答标题问的那件事吗」，答不上来就改标题或改内容——
**不要靠加一条硬规则来补**。此前「第一页必须报模型名」就是错误示范：
它是结果，不是原因。正确做法是让每页标题问一个能真实回答的问题。

| 页面标题在问 | 这页必须给 | 例子 |
|---|---|---|
| 是什么 / 是谁 | 定义 + 归属（厂商、发布时间、什么架构） | Beam = Reflection AI 10/5 发布的稀疏 MoE |
| 为什么这么做 | 动机、背景 | 欧盟法案第 50 条要求机器可识别 |
| 怎么做的 | 方法、步骤、投入 | 6144 张 GB300 预训练 + 10500 张做 RL |
| 有多强 / 凭什么是它 | 可核验的数字 + **必须带的反方** | 官方跑分 80.9，同时承认 Kimi K3 裸能力更强 |
| 值不值得用 | 门槛、成本、适合谁 | 单卡 H200 可跑，78GB FP8 |
| 有什么坑 | 局限、短板 | 1M 是验证过不是推荐用，建议 ≤262K |

**自查动作**：出图前把每页 `title` 列出来，逐条问「这页内容真的回答了它吗」。
2026-10-06 实测事故：正文第一页标题写「是什么」，内容却全是性能对比 ——
标题承诺定义、内容给的是跑分，读者读到第 5 页仍不知道在讲哪个模型。

⚠️ **模型名/产品名不是硬规则，是逻辑结果**：
- 页面要回答「是什么 / 是谁」→ **必须**给全名 + 厂商
- 页面要回答「怎么做的 / 有多强」→ 用简称即可，不必重复定义
- 全篇都不出现名字才是不合理（读者无从定位谈的是谁），而不是「第一页必须报名字」

删减要在同页内做：补完信息若密度掉到 78% 以下，从后续页删掉**与本页重复**的表述
（通常是刚移过来的那条），不要新加页。2026-10-06 实测：Beam 删到 4 条掉到 70.6%，
补回被移走的那条才过——**删减要挑「被前移的那条」，不是随便减条数**。

#### 钩子的心理学依据（2026-10-06 调研，别凭感觉写）

**钩子不是标题党，靠的是信息缺口（好奇心缺口），不是夸大。**

- 洛温斯坦「信息缺口理论」：读者意识到「已知」与「想知」之间有缺口时会产生轻度焦虑，
  驱使其点进来弥合。
- **反常识型钩子最稳**：挑战已有认知（预期 × 实际 = 认知冲突）。
- ⚠️ **CHI2021 实证反直觉结论**（Penn State，三项 clickbait 研究）：
  **非标题党标题的总点击量高于七类标题党特征中的四类、与其余三类持平。**
  原文口径：「despite the common understanding that clickbait headlines generate more clicks
  than non-clickbait, this is not the case.」
  且非标题党被感知为**更少欺骗感、更可信**。
  → 所以**不必为了点击去写夸张句**，钩子应落在「真实的认知落差」上
  （官方承认别人更强 / 网传说法官方表格里根本没有 / 数字反而更大）。
  → **禁忌**：用「震撼」「惊了」类词，平台明确限流，且这些特征实测并不带来更多点击。

平台侧口径（2026-09 运营资料）：小红书**封面决定约 60% 点击率**，主标题建议 10 字以内；
正文三段式为「开头钩子 → 中间干货 → 结尾互动」，完读率与收藏权重高于点赞。

1. **尺寸校验**：用 Python + Pillow 读回真实像素，确认 2160×2880、ratio 0.750

2. **密度校验**：**`make.py` 已直接输出，不用另跑脚本。**
   看最后一行 `RESULT bad=N low=M(不阻断)` —— `bad` 只统计 `CROWD` / `OVERFLOW` / `WRAP`，
   **`low` 不阻断**（填充偏松不是缺陷，2026-10-08 起）。**`bad=0` 即通过**。
   > ⚠️ 旧的 `scripts/check_density.py`（Pillow 扫像素）**不要再跑**：
   > 它把封面光晕、贴底脚注都当内容，读数有硬伤；`render2.cjs` 的 DOM 直测已取代它。

3. **看图（按需，不要逐页看）**：只开两类页 ——
   ① **封面**（确认大字没换行，两平台各一次）；
   ② 有 `CROWD` / `OVERFLOW` / `WRAP` 告警的页。
   **填充 `OK` 的内页不要逐张打开**，看图慢且占上下文，DOM 读数已经够用。

4. **违禁词自检**（发布前最后一道闸，不可跳过）：
   检测**标题 / 正文 / 标签 / 图上文案**。**命中高危词必须改掉再发**——
   《广告法》第九条的绝对化用语（最好、唯一、100%、国家级…）属于直接违法风险。

   ```bash
   "$PY" "$SKILL/scripts/check_banned_words.py" --meta 'meta_xxx.json' --html 'cards_xxx.html'
   ```

   退出码 **2 = 有高危**（必须改）；**1 = 只有中危**（建议改）；**0 = 通过**。
   词库在 `scripts/banned_words.json`，9 类：绝对化用语 / 医疗功效 / 金融诱导 / 迷信 /
   违禁品类 / 站外导流 / 敏感营销词 / 伪科学 / 弱极限词（需人工判断）。
   ⚠️ 词库覆盖不到的：**图上文字**如果改过，记得重新跑 `--html` 那一路。

#### 出图命令（走工具链，别手写补丁脚本）

**出图流水线已随本skill 收进仓库**：`pipeline/` 目录，跨 Windows / Linux / macOS。
换设备或云端第一件事跑自检，确认路径与解释器解析正确：

```bash
python "$SKILL/pipeline/make.py" --doctor
```

工作目录里放 spec（**推荐 `card.json` 一份内容出两平台**），然后：

```bash
P="$SKILL/pipeline"

python "$P/make.py" <工作目录>                  # 生成→违禁词预检→收敛 gap→测量→截图→回写
python "$P/make.py" <工作目录> --tag <YYYYMMDD_主题>   # 顺带交付到两平台成品目录
python "$P/make_all.py" --root <根目录> --workers 3 # 批量，多目录并行
```

`make.py` 会按 spec 自动跑两遍并注入各自 `data-platform`；
只有需要两平台各写各的时才退回 `xhs.json` + `douyin.json` 两份。

> 交付根目录由环境变量 `XHS_DIR` / `DY_DIR` 指定；**只有传 `--tag` 时才需要**，
> 不设则只出图不交付（非 Windows 上默认就是这种）。详见 `pipeline/README.md`。

> ⚠️ **`card.json` 模式下 gap 不回写 spec** —— 两平台字号档位不同，同一个 gap 值
> 给抖音会偏紧。`autogap` 每次运行都会重新收敛，不要手工把值写进 `card.json`。

`card.json` 结构：

```jsonc
{
  "theme": "midnight",          // 5 套统一主题，可整篇
  "html_theme": "midnight",     // 背景与配色用的那一套
  "pages": [
    { "type": "cover", "export": "01-封面.png", "theme": "ember",
      "chip": "AI 前沿", "corner": "行业事件",    // corner = 小红书右上角栏目词
      "idx": "01/08",                            // 抖音右上角连号页码
      "compact": true,                           // 榜单类封面：标题缩小、版面让给 blocks
      "kicker": "…", "title": "…", "title2": "…", "title3": "…", "desc": "…<br>…",
      // 大字最多三行：title(白) / title2(紫) / title3(白)，白紫白交替。
      // ⚠️ 行放不下时先降 title_fs，不要往字段里塞 <br>（会误报 WRAP）。
      // 小字/大字都可单独调（绝对值 px，只在本页生效，不动全局档位）：
      // kicker_fs / kicker_ls / title_fs / title2_fs / title3_fs。字距不传时按字号 0.2 倍自动。
      // ⚠️ 只给 kicker_ls 时不写死 font-size，两平台各用自己档位。
      "kicker_ls": 2, "title_fs": 100, "title2_fs": 100, "title3_fs": 100,
      // 行内关键词换色（2026-10-09 新增）：每行挑 1 个词换色做视觉焦点。
      // 值必须是**该行文本里逐字出现的片段**，否则静默不生效（build_cards 会打 WARN）。
      // 配色自动：白行(title/title3)的高亮取主题强调色；title2 行本身是强调色，高亮反而取白色。
      "title_hl": "Gemini 4", "title2_hl": "办公 Agent", "title3_hl": "Claude",
      "blocks": [                                // 封面也能放 blocks（榜单用）
        {"k": "ranklist", "v": [
          {"r": "1", "n": "dots", "d": "一句话定位", "inc": "+30,974", "top": true},
          {"r": "6", "n": "ponytail", "inc": "+8,610"}
        ]}
      ],
      "stats": [["5", "处命中"], ["2", "个角度"]],
      "swipe": "左滑看完全部 8 张" },

    { "type": "inner", "export": "02-xxx.png", "theme": "…",
      "brand": "栏目", "mark": "子栏目",
      "idx": "02/08",            // 抖音连号
      "page": "01",              // 小红书页码
      "title": "第一行<br>第二行", "rule": true, "gap": 46,
      "blocks": [
        {"k": "warn",   "v": "…"},
        {"k": "items",  "v": [{"t": "…", "d": "…"}]},
        {"k": "points", "v": ["…"]},
        {"k": "data",   "v": [["88%", "标签"]]},
        {"k": "sub",    "v": "…"}
      ],
      "foot": "来源：36氪 · 量子位" }
  ]

```

支持的全部 `k`：`warn` / `items` / `points` / `data` / `sub` / `rank` / `raw` / **`ranklist`**。

`chip` / `corner` / `idx` / `swipe` / `page` 这些平台专属字段**留空即可**，
`build_cards.py` 会按 `data-platform` 自动派生（小红书补 `page`，抖音补 `idx` / `swipe`）。

> ⚠️ **封面标题不要在 `title` 里塞 `<br>`** —— 会触发 `WRAP` 告警（测出来的是
> 「单词不换行」，不是排版问题）。**两行封面标题必须用 `title` + `title2` 两个字段**，
> `<br>` 只用于 `desc` 和内页 `title`。

### 榜单类封面：`compact` + `ranklist`（2026-10-07 实测跑通）

**场景**：一页要放完 10 条榜单（周榜 / 日榜 / 各类排行）。

**必须写 `compact: true`。** 否则标题区占掉约 200px，10 条塞不进，且 `title2` 会换行触发 `WRAP`。
compact 下会：标题降到 66/58px（抖音 70/62）、隐藏 `.cv-line`、`.cv-body` 改为 `flex:0 0 auto`、
榜单 gap 用单独的 `--rl-gap-compact`（小红书 6px / 抖音 5px）。

**收敛 10 条排满一屏的顺序**（实测 262 → 92 → 43 → 0）：

| 手段 | 效果 |
|---|---|
| 压缩 `--fs-rl-*` / `--rl-gap` / `--rl-row-pad` 档位 | 每档 10–40px |
| `compact` 下隐藏 `.cv-line`、删掉 `desc` | 约 90px |
| 调 `--rl-gap-compact` | 每 1px ≈ 5px |

> ⚠️ **`gap` 内联属性对 `--rl-gap` 无效** —— CSS 变量优先级高于内联 style。
> 封面要单独更紧的间距，**必须加 `--rl-gap-compact` 变量并用 `.cover.compact .ranklist` 挂上**，
> 改 `card.json` 里的 `gap` 字段没有任何效果（会静默无效，最容易白跑一轮）。

**`ranklist` 的强弱分档与渐变**（用户明确要求过两次）：

- `top: true` = 1–5 名（实心徽章 + 主题色底 + 一句话描述）；不带 `top` = 弱化档。
- 弱化档**必须做成渐变，不能一刀切**。`build_cards.py` 会按名次自动给弱化档行内
  `opacity`：第 6 名 0.85，每往后一名 −0.05，下限 0.6。
- ⚠️ **弱化档的徽章必须用实心 + 半透明底，不能用空心边框。**
  空心边框本身只有 `rgba(255,255,255,.22)`，叠上 opacity 后轮廓直接消失，
  第 10 名实测只剩一条竖线。实心 `rgba(79,142,255,.55)` 才能形成连续的蓝色渐变带。
- 字号差也收窄：1–5 名 26px → 6–10 名 22px（抖音 28 → 24），不是 26 → 20。
- **项目名只写仓库名**（`HowToLiveBetter`），**不写 `owner/repo`** —— owner 是发布人，
  读者不关心，占地方。owner 放项目页正文首句。

**封面上不要重复同一件事**（用户 2026-10-07 明确）：
`chip` 写「GitHub周榜」，口径（按 N 天新增星数）**跟在抓取时间后面写进 `desc`**：

```
"chip":  "GitHub周榜",
"title": "本周涨星前10",
"title2": "第2名是本中文书",
"desc":  "2026-10-07 抓取 · 按 7 天新增星数"
```

⚠️ **口径不要单独占一行 `kicker`。** 用户原话：「按七天新增星数不是重点，写在抓取时间后面即可。」
`kicker` 是 38–40px 字号 + 26px 下边距 ≈ **76px**，在 compact 封面里是宝贵空间，
拿它放一句口径太浪费。删掉后把空间让给主语字距，视觉更值钱。

**compact 封面的主语要放开字距**（同一轮用户要求：「主语的间距加大一些，没那么拥挤」）。
默认 `--ls-cv-title` 是**负值**（小红书 −2px / 抖音 −3px，大字紧排是通用做法），
但 compact 下字号只有 66/70px，负字距看起来拥挤。compact 另给一档**正字距**
`--ls-cv-title-c`（小红书 +3px / 抖音 +4px），并给 `title2` 加 `--cv-title2-mt`
（8/9px）——**两行之间也要留白，只放开字距不够**。

### ⑦ 汇总 HTML（单文件、可直接双击打开）

**不要把一堆散图当交付物。** 用户明确反馈过「展示内容过于零散，最好集合到一个文档或 HTML」。

用 `scripts/build_preview.py` 生成单文件 HTML，图片以 base64 内嵌，离线可开：

```
python build_preview.py --cards <output目录> --out <汇总.html> --meta <meta.json>
```

汇总页包含五块：元信息条 → 一键复制的标题/正文/标签 → 图文预览 → 事实核验表 → 来源清单与发布步骤。

**交付时把汇总 HTML 放第一个**，PNG 放在后面。

#### ⚠️ `meta_*.json` 的字段名（写错会静默丢 HTML，2026-10-06 实测）

| 字段 | 正确写法 | 写错的后果 |
|---|---|---|
| `titles` | `[{"style": "事实型", "text": "标题文字"}, ...]` | **字符串数组会报** `'str' object has no attribute 'get'` |
| `tags` | `["AI", "开源模型"]` | 写成 `topics` → 校验脚本说「没有 tags 字段」，话题数不检查 |
| `body` | 纯字符串 | — |

> **典型症状**：PNG 正常出图，`RESULT bad=0`，但交付只有「6 张 PNG | 0 个 HTML」。
> 这不是渲染问题，是 meta 结构错。**看到 0 个 HTML 立刻查 titles 格式。**

#### 抖音封面比小红书更容易换行

抖音字号比小红书大一号（`--fs-*` 更大），**在小红书侧不换行的标题，抖音侧可能换行**，
触发 `WRAP` 告警。实测「5010 亿只激活 230 亿」小红书正常、抖音拉成两行。
**做法：抖音封面第二行控制在 6 个汉字内**，或换更短的钩子。

**认知度锚点规则两平台共用，但钩子不能重复**（2026-10-06 实测）：
抖音大字同样给「读者已认识的东西」，但**第二行钩子要另起一套**，不能照抄小红书版。
实测范例：

| 选题 | 平台 | 大字第一行 | 第二行（钩子） |
|---|---|---|---|
| Beam | 小红书 | `英伟达投资了` | `一家开源模型公司` |
| Beam | 抖音 | `英伟达` | `投了一家模型公司` |
| textGrain | 小红书 | `OpenAI` | `给文字打隐形水印` |
| textGrain | 抖音 | `OpenAI` | `悄悄给文字打了水印` |
| Kolibri | 小红书 | `又来一个新模型` | `单张H200就能跑` |
| Kolibri | 抖音 | `新模型` | `欧洲自己造了一个` |

⚠️ **封面文案改一个字都必须重出图**：封面 `title` / `title2` / `desc` 在
`xhs.json` 与 `douyin.json` 里**各存一份**（`to_douyin.py` 只做结构转换，**不会同步文案**）。
改完记得两个文件都改，再 `make.py` 重跑。

### ⑧ 刷新「内容成品总索引」（每做完一批都要跑，别忘）

**用户 2026-09-30 反馈：新成品做完了，但索引页里没有。** 根因是这个索引生成器一直是
「孤岛脚本」—— 流程里没写、AI 每次都想不起来跑，于是索引停在某一版不动（实测停了 2 天）。

```bash
python scripts/build_index.py
# 默认输出 <小红书根目录>\内容成品总索引.html；它同时扫两平台根目录
```

- **时机**：⑦ 做完、交付文件都落盘之后，**立刻跑一次**。一次跑就覆盖两平台，不用跑两遍。
- **它扫什么**：`<YYYYMMDD>_<主题>\` 形式的成品目录（内含至少 1 个汇总 HTML），
  以及 `选题\` 里的选题池 HTML。`合集封面` / `发布助手` / `选题` / `.workbuddy` / `_build` 会被跳过。
- **索引统一放小红书根目录**（这是唯一一份，抖音不另存）。
- **不刷新 = 用户找不到东西。** 这条和出图、汇总页同等重要，不是可选项。

## 环境

### 依赖清单

| 组件 | 必需 | 说明 |
|---|---|---|
| **Python 3.8+** | ✅ | 跑 `pipeline/` 与 `check_*.py` / `build_*.py` |
| **Node.js 18+** | ✅ | 跑 `pipeline/render2.cjs` |
| **playwright-core** | ✅ | 渲染依赖，需用 `NODE_PATH` 引入（或设 `NODE_BIN` + 装到本地） |
| **Chromium** | ✅ | 出图内核。脚本自动扫描 Windows / Linux / macOS 常见位置 |
| 中文字体 | 必需 | 缺了中文会渲染成方块。Debian 系 `apt install fonts-noto-cjk` |
| Pillow | 视情况 | **出图链路不需要**（`render2.cjs` 用 DOM 直测密度，不解图）。只有手动跑旧像素方案 `check_density.py` 时才要 `pip install Pillow` |
| Git | 出图**不需要** | 只在 `git clone` / 推送时用 |

> **出图链路（`pipeline/`）只依赖标准库 + Node 内置模块**，不需要 pip 装任何东西。

### 环境自检（换设备第一条命令）

```bash
python scripts/env_check.py          # 本机自检
python scripts/env_check.py --net    # 附带网络可达性
python scripts/env_check.py --json   # 机器可读
python pipeline/make.py --doctor     # ★ 出图链路单独自检（路径 / 解释器 / 成品根目录）
```

`env_check.py` 报出 Python / Node / playwright-core / Chromium / Pillow / 中文字体 / 成品目录的实际状态，
`make.py --doctor` 报出流水线**实际会用到的**路径与解释器。**换机器或上云端时先跑这两个，
不要照抄任何写死的路径。**

> ⚠️ **`make.py` 的工作目录必须转绝对路径**（`os.path.abspath`）。它把 `--report` 传给
> 在 `cwd=工作目录` 里跑的 `render2.cjs`，若传相对路径会拼成 `<工作目录>\<目录>\`，
> 报告写不出来。此时 `os.path.exists(报告)` 靠的是**上一轮的旧文件**，
> 表现是 `gap_writeback=0` 但**静默用了陈旧数据** —— 不报错，最难查。
> 2026-10-06 已修；改这个脚本时别把 `abspath` 去掉。
>
> ⚠️ 同理，**不要在任何脚本里写死 Node 版本号**（如 `versions\22.22.2-5\node.exe`）。
> 本机升级后会变成 `-6`，路径直接失效。`pipeline/_paths.py` 已改为
> `NODE_BIN` → `PATH` → 读 `versions\current` 指针 → 扫版本目录。
> **新增环境相关解析一律加到 `_paths.py`，别散在各个脚本里。**

### 跨设备时的路径覆盖

输出目录三级配置，优先级：**CLI 参数 > 环境变量 > `config.json` > 内置默认**。

| 环境变量 | `config.json` 键 | 含义 |
|---|---|---|
| `XHS_DIR` | `xhs_dir` | 小红书成品根目录 |
| `DY_DIR` | `dy_dir` | 抖音成品根目录 |
| `INDEX_OUT` | `index_out` | 总索引输出路径 |

`config.sample.json` 是配置模板，**复制为 `config.json` 后按本机实际改**。
`config.json` 已被 `.gitignore` 排除，**不会把本机绝对路径提交到仓库**。

云端（Linux 沙箱）示例：

